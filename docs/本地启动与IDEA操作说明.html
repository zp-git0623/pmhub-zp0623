PmHub 本地启动与 IDEA 操作说明

覆盖单体版与微服务版的依赖准备、命令行启动、IntelliJ IDEA 配置、前端登录和常见问题。首次运行建议先按单体版步骤验证环境。

本页目录先选版本Redis 启动与验证单体版启动IDEA 启动单体版前端登录账号微服务版启动IDEA 启动微服务常见问题停止服务

1. 先选版本

单体版（推荐首次启动）

后端入口在 pmhub-boot，需要 MySQL、Redis；页面代理到 5010 端口。

适合本机试运行、调试业务和 IDEA 单服务启动。

微服务版

后端位于仓库根目录，由 Gateway、Auth、System、Project 等服务组成；依赖 MySQL、Redis 和 Nacos。

适合调试服务拆分、注册发现和配置中心。

不要混用前后端目录：单体前端是 pmhub-boot\pmhub-ui，微服务前端是根目录 pmhub-ui。它们分别代理到 5010 和 6880。

环境要求

组件说明
JDK使用 JDK 8。IDEA 的 Project SDK、Maven Importer 和 Maven Runner 均设为 JDK 8。
MavenREADME 标注 Maven 3.9.1；确保 Maven 进程实际运行在 JDK 8 上。
MySQL单体 SQL 来自 MySQL 8.0 导出；按本机数据库配置连接信息。
Redis单体默认连接 127.0.0.1:6379，无密码。
Node.js / npm用于启动 Vue 前端；按对应目录中的 lockfile 选择安装命令。

Redis：本地启动与验证（两种版本通用）

本机可以直接使用现有安装：D:\software\redis\5.0.14.1 内有 redis-server.exe 和 redis-cli.exe，无需为启动 Redis 先启动整套微服务。单体本地配置为 127.0.0.1:6379、数据库 0、密码为空；前端登录密码 123456 不是 Redis 密码。下面命令均在 PowerShell 执行。

R.1 先确认是否已经启动

Test-NetConnection 127.0.0.1 -Port 6379
& 'D:\software\redis\5.0.14.1\redis-cli.exe' -h 127.0.0.1 -p 6379 PING

TcpTestSucceeded : True 只说明端口可连接；PING 返回 PONG 才说明 Redis 能正常响应。已经返回 PONG 就不用重复启动；若连接被拒绝，再按 R.2 操作。Windows 与 Docker 两种方式选一种，不要同时占用 6379。

R.2 使用本机现有 Windows Redis 启动

新开 PowerShell 窗口，复制下面整段。数据单独放在当前用户的 AppData\Local\PmHub\redis-data，不会写进 Redis 安装目录或项目源码目录：

$redisHome = 'D:\software\redis\5.0.14.1'
$redisData = Join-Path $env:LOCALAPPDATA 'PmHub\redis-data'
New-Item -ItemType Directory -Path $redisData -Force | Out-Null
& "$redisHome\redis-server.exe" --bind 127.0.0.1 --port 6379 --protected-mode yes --dir "$redisData" --appendonly yes

看到 Ready to accept connections 后，保持这个窗口开启，另开终端执行 R.1 的 PING 验证，再启动 Java 后端。命令以前台进程方式运行，不会注册 Windows 服务；重启电脑后需要重新执行。换电脑时将 $redisHome 替换为实际解压目录。

该命令沿用本机已有的 Windows 5.0.14.1 包，仅用于本地开发，不代表测试或生产部署方案。无密码示例只允许本机访问，不要为了远程连接改为对公网开放。

R.3 从 IDEA 中启动

  1. 打开 IDEA 底部 Terminal，选择 PowerShell，执行 R.2 的整段命令，保留该终端标签页。
  2. 再打开一个 Terminal 标签页，执行 R.1 的 PING；看到 PONG 后，再用 Run / Debug 启动单体主类或各微服务主类。
  3. IDEA 的 Java Run 配置不会自动启动 Redis。停止 Java 后端也不会自动停止 Redis；如要停止 Redis，见 R.5。

R.4 核对项目的 Redis 连接配置

单体版核对 D:\projects\pmhub\pmhub-boot\pmhub-admin\src\main\resources\application-local.yml 中已有的 spring.redis 节点；下面只是配置片段，不要覆盖整个文件，也不要重复添加顶层 spring 节点：

spring:
  redis:
    host: 127.0.0.1
    port: 6379
    database: 0
    password: ""

微服务版在 Nacos 中检查当前 profile 对应的配置，例如 application-dev.yml 和各服务自己的 *-dev.yml，以实际生效的 spring.redis 为准。后端从 Windows / IDEA 启动且 Redis 也在本机时使用 127.0.0.1；后端也在 Docker 容器里时，不要把容器内的 127.0.0.1 当成宿主机。使用仓库 Compose 且处于同一网络的后端应连接 Redis 服务名 pmhub-redis。

若你自行给 Redis 设置了密码，需要同步设置后端的 spring.redis.password；没有设置密码时保持为空，不要填写前端登录密码。

备用方式：已有 Docker Desktop 时启动 Redis

先启动 Docker Desktop，使用 Linux containers，并确认 docker version 能显示 Server 信息。确认 Windows Redis 未占用 6379 后，首次创建执行：

docker run -d --name pmhub-redis-local -p 127.0.0.1:6379:6379 -v pmhub-redis-local-data:/data redis:7.4 redis-server --appendonly yes
docker exec pmhub-redis-local redis-cli PING

预期返回 PONG。示例将端口发布到宿主机回环地址，数据保留在命名卷中；Redis 7.4 是备用镜像示例，本次未运行该镜像或验证完整项目兼容性。不要同时再用仓库 Compose 启动另一个占用 6379 的 Redis。

下次已有同名容器时，不要重复 docker run，而是执行：

docker start pmhub-redis-local
docker exec pmhub-redis-local redis-cli PING

容器名称冲突时先用 docker ps -a --filter "name=pmhub-redis-local" 查看，不要直接删除现有容器或数据卷。

R.5 停止 Redis

先停止依赖它的 Java 服务。Windows 前台方式可在 Redis 窗口按 Ctrl+C，或在另一个终端执行下面命令正常关闭本地无密码实例：

& 'D:\software\redis\5.0.14.1\redis-cli.exe' -h 127.0.0.1 -p 6379 SHUTDOWN

如果采用上面的 Docker 方式，则执行：

docker stop pmhub-redis-local

参考：Redis 命令行配置、redis-cli 连接与验证、Docker 端口映射、Compose 服务网络。这些无密码命令仅针对本机隔离开发环境。

2. 单体版：命令行启动

本机已验证的配置：JDK 8、MySQL 127.0.0.1:3306/laigeoffer-pmhub、Redis 127.0.0.1:6379、后端端口 5010。数据库用户名、密码以 application-local.yml 为准，仅用于隔离的本地开发环境，不要用于生产。
1

确认 Java 与 Maven 使用 JDK 8

在 PowerShell 设置当前终端环境；JDK 安装位置不同时替换路径。

$env:JAVA_HOME = 'C:\Program Files\Java\jdk1.8.0_202'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
java -version
mvn -version

两条版本输出都应显示 Java 1.8。若 Maven 显示 Java 21 等其他版本，先修正 JAVA_HOME。

2

启动 MySQL 和 Redis

Redis 请先按「Redis 启动与验证」操作并确认返回 PONG，再确认 MySQL 已运行并检查端口：

Test-NetConnection 127.0.0.1 -Port 3306
Test-NetConnection 127.0.0.1 -Port 6379

配置位置：pmhub-boot\pmhub-admin\src\main\resources\application-local.yml。

3

导入单体数据库

SQL 文件为 pmhub-boot\sql\pmhub_20240305.sql。在 cmd.exe 执行，提示时输入 MySQL 密码：

mysql -u root -p -h 127.0.0.1 -P 3306 < "D:\projects\pmhub\pmhub-boot\sql\pmhub_20240305.sql"

也可用 Navicat 执行。脚本会创建 laigeoffer-pmhub 并重建其中部分表；导入前备份同名数据库里的重要数据。

4

启动后端

新开 PowerShell 窗口：

cd D:\projects\pmhub\pmhub-boot
mvn -pl pmhub-admin -am -DskipTests package
java -jar .\pmhub-admin\target\pmhub-admin.jar

启动成功后后端地址为 http://127.0.0.1:5010。

5

启动单体前端

cd D:\projects\pmhub\pmhub-boot\pmhub-ui
npm ci
npm run dev -- --port 3000

npm ci 按 package-lock.json 安装依赖。浏览器打开 http://localhost:3000。

3. IDEA：启动单体版

  1. IDEA 选择 Open，打开 D:\projects\pmhub\pmhub-boot，导入其中的 pom.xml 为 Maven 工程。
  2. File → Project Structure → Project：Project SDK 设为 JDK 8。
  3. Settings → Build Tools → Maven：Maven Importer JDK、Runner JRE 均设为该 JDK 8；Maven Home 选已安装 Maven 或 IDEA bundled Maven。
  4. 等待同步，在 pmhub-admin 中找到主类 com.laigeoffer.pmhub.PmhubApplication。
  5. 右键选择 Run 'PmhubApplication.main()'。手工配置时：类型 Application；Main class 填上述类名；Use classpath of module 选 pmhub-admin；Working directory 为 D:\projects\pmhub\pmhub-boot；JRE 选 JDK 8。
  6. 运行后端前先启动 MySQL，并按「Redis 启动与验证」确认 Redis 返回 PONG。IDEA Terminal 中进入 D:\projects\pmhub\pmhub-boot\pmhub-ui，执行 npm ci 和 npm run dev -- --port 3000。
若 IDEA 导入的是仓库根目录微服务 Maven 工程，不要在该工程中启动单体主类；单体工程应导入 pmhub-boot\pom.xml。

4. 前端登录账号与密码

登录页：单体版 http://localhost:3000；微服务版 http://localhost:1024。

演示登录密码没有在当前仓库文档中公开。本地导入仓库初始化 SQL 后，超级管理员账号为 admin，密码为 123456。我用项目所依赖的 BCrypt 编码器核对过单体 SQL 与微服务 System SQL 中的初始密码哈希。该账号仅适用于本地初始数据库，首次登录后建议修改。仓库 README 提及的在线演示账号是另一套账号：关注微信公众号「苍何」，回复 pmhub 获取。数据库连接口令也不是前端登录密码。

使用自己的本地账号时，确认已导入初始化数据，或通过项目用户管理/密码重置流程设定。不要把真实账号密码提交到 Git。

Nacos 控制台账号与 PmHub 前端账号不同：仓库 README 标注本地 Nacos 默认用户名和密码均为 nacos。

5. 微服务版：命令行启动

微服务需要 MySQL、Redis、Nacos 和 Nacos 配置数据。根目录 docker\docker-compose.yml 是整套容器部署配置，不等同于只启动基础依赖。

5.1 准备配置中心和数据库

  1. 启动 MySQL，按「Redis 启动与验证」启动 Redis 并确认返回 PONG。各服务默认使用 Nacos 127.0.0.1:8848，Nacos 默认账号密码为 nacos。
  2. SQL 位于根目录 sql。Nacos 本地安装的 conf\application.properties 需配置为本机可访问的数据库地址，并与 Nacos 数据库用户配置匹配。

以下命令在 cmd.exe 中逐条执行，按提示输入 MySQL 密码：

mysql -u root -p -h 127.0.0.1 -P 3306 < "D:\projects\pmhub\sql\pmhub_nacos.sql"
mysql -u root -p -h 127.0.0.1 -P 3306 < "D:\projects\pmhub\sql\pmhub-system.sql"
mysql -u root -p -h 127.0.0.1 -P 3306 < "D:\projects\pmhub\sql\pmhub-project.sql"
mysql -u root -p -h 127.0.0.1 -P 3306 < "D:\projects\pmhub\sql\pmhub-workflow.sql"
mysql -u root -p -h 127.0.0.1 -P 3306 < "D:\projects\pmhub\sql\pmhub-gen.sql"

Nacos 使用 MySQL 时，按其 application.properties 配置的库名、用户和密码准备连接；仓库示例库名为 pmhub-nacos。仅使用 Seata 时再导入 sql\pmhub_seata.sql。

在 Nacos 的 bin 目录启动（替换为实际 Nacos 安装路径）：

cd C:\path\to\nacos\bin
.\startup.cmd -m standalone

打开 http://localhost:8848/nacos，确认以下 Data ID 存在且连接配置已按本机环境修改：application-dev.yml、pmhub-gateway-dev.yml、pmhub-auth-dev.yml、pmhub-system-dev.yml、pmhub-project-dev.yml、pmhub-workflow-dev.yml、pmhub-gen-dev.yml、pmhub-job-dev.yml、pmhub-monitor-dev.yml。

5.3 启动微服务前端

6. IDEA：启动微服务

  1. IDEA 打开 D:\projects\pmhub，导入根目录 pom.xml，等待多模块 Maven 同步完成。
  2. Project SDK、Maven Importer JDK、Maven Runner JRE 全部设为 JDK 8。
  3. 先启动 MySQL、Redis、Nacos，并确认 Nacos 数据源和 Data ID 可用。
  4. 在各模块找到对应 Application 主类，右键 Run。顺序：Gateway、Auth、System、Project、Workflow、Gen、Job、Monitor；各主类和端口见上表。
  5. 确认服务启动并注册到 Nacos 后，在 IDEA Terminal 进入根目录 pmhub-ui，执行 npm install、npm run serve -- --port 1024。

手工配置时选 Application，Main class 填上表全限定类名，Use classpath of module 选对应 Maven 模块（如 pmhub-gateway、pmhub-system），JRE 选 JDK 8。默认 profile 为 dev，Nacos 地址在各模块的 src\main\resources\bootstrap.yml。

7. 常见问题

Maven 报 Java 版本不支持，或 IDEA 与终端结果不同

检查 java -version、mvn -version 和 IDEA 的 Project SDK、Maven Importer JDK、Runner JRE，全部设为 JDK 8。PowerShell 的 JAVA_HOME 不会自动改变 IDEA Maven Runner。

MySQL Access denied、Unknown database 或连接超时

单体检查 application-local.yml 中 JDBC URL、用户名和密码，并确认导入单体 SQL；微服务检查 Nacos 中各个 *-dev.yml 配置。确认数据库服务端口与 JDBC URL 一致。

Redis 连接失败、认证失败或端口被占用
  • Connection refused：先按「Redis 启动与验证」启动，并用 PING 确认返回 PONG。只打开 redis-cli.exe 并不会启动 Redis 服务端。
  • NOAUTH Authentication required：当前 Redis 需要密码，同步核对后端 spring.redis.password 和实际 Redis 密码。
  • ERR Client sent AUTH, but no password is set：服务端未设置密码，但客户端填写了密码；本地无密码实例应把后端密码留空。
  • 6379 被占用：先执行 Get-NetTCPConnection -LocalPort 6379 -State Listen，通过 OwningProcess 确认占用进程；不要直接结束未知进程。若现有 Redis 已返回 PONG，不必再启动第二个。
  • IDEA 正常但后端仍报错：确认实际激活的 profile；单体检查 application-local.yml，微服务检查 Nacos 中实际生效的 spring.redis。
找不到 Nacos 配置或注册中心

确认 Nacos 可访问、账号有效、8848 端口可用，所需 Data ID 存在。Windows 主机运行服务时不要将 Docker 内部服务名直接用作地址。

前端端口被占用

换用空闲端口，如单体 npm run dev -- --port 3001、微服务 npm run serve -- --port 1025。后端代理目标仍是 5010 和 6880。

npm 安装失败或 OpenSSL 报错

检查 Node.js/npm 和 registry 网络；单体前端优先使用 npm ci。微服务前端 Windows 下可用 npm run serve，必要时设置 NODE_OPTIONS 后重试。

8. 停止服务与常用地址

  • 命令行前端、后端：各自终端按 Ctrl+C；IDEA 服务点击 Run 面板停止按钮。
  • 按Redis 章节 R.5停止手动启动的 Redis；由 Windows 服务管理器启动的 MySQL/Redis/Nacos，按本机服务管理方式停止。
  • 单体前端：http://localhost:3000；API：http://127.0.0.1:5010。
  • 微服务前端：http://localhost:1024；Gateway：http://127.0.0.1:6880；Nacos：http://localhost:8848/nacos；监控：http://localhost:6888/wallboard。
说明依据当前仓库 README、Maven 模块、服务配置和前端配置整理。启动前请以本机实际数据库、Redis、Nacos 配置为准；前端演示账号密码按仓库说明通过公众号获取。
